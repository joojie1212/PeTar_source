# Optional NFW initial conditions for PeTar

Build with `make mcluster DARKMATTER=1` (or `make mcluster_sse DARKMATTER=1`).
A plain `make mcluster` builds the original feature set. The targets rebuild
when invoked, so switching the macro does not leave a stale executable.
The new C source, options and call sites are guarded by DARKMATTER. A macro-on
binary without --dm-nfw follows the original generation and output path.

## Example

```sh
make mcluster DARKMATTER=1
./mcluster --dm-nfw \
  --dm-number 4096 --dm-mass 10000 --dm-rs 10 --dm-rt 100 \
  --dm-softening 1 \
  -N 1024 -f 0 -m 1 -R 1 -P 0 -t 0 -s 42 -o halo
```

This produces halo.star, halo.dm, halo.dm.profile and halo.dm.info.
The stellar mass function is still generated by McLuster: -N/-M and -f/-m
retain their meanings. The actual sampled stellar mass is used in the potential.
No subsequent isolated-star virial rescaling is applied.

| Parameter | Meaning |
| --- | --- |
| --dm-nfw | Enable the new generator. |
| --dm-number | Number of equal-mass DM particles; required. |
| --dm-mass | Total mass of the **tapered** halo, in Msun; required. This is not M200 or mass inside rt. |
| --dm-rs | NFW scale radius, pc; required. |
| --dm-rt | Smooth outer taper scale, pc, at least rs; required. Not a hard edge or a cosmological virial radius. |
| --dm-softening | Positive Plummer softening for DM interactions, pc; required. |
| --dm-grid | Logarithmic radial/energy grid size, 512--8192; default 2048. |
| --petar-interrupt | Stellar output layout: none (default, 20 columns) or bse (34 columns). Must match the PeTar build. |
| -R | Analytic stellar Plummer half-mass radius, pc. The finite sample fluctuates around this value; it is not rescaled afterward. |
| -s | McLuster random seed. |

## Density and equilibrium

An infinite NFW profile has infinite mass. This implementation uses

```text
x = r/rs, y = r/rt
rho_dm(r) = rho_s / [x (1+x)^2 (1+y^2)^2]
rho_star(r) = 3 Mstar/(4 pi a^3) (1+r^2/a^2)^(-5/2)
a = Rh sqrt(2^(2/3)-1)
```

rho_s is normalized to --dm-mass. The inner NFW cusp is retained; the taper
changes the outer slope to -7 and avoids a discontinuous density edge. It also
changes density inside rt, increasingly near rt. Particles can lie outside rt.

Both components are isotropic and generated by Eddington inversion, including
BOTH stellar and DM gravity. Velocities are sampled from the resulting
conditional speed CDF; they are not Gaussian Jeans approximations.

PeTar leaves star-star forces unsoftened and softens all interactions involving
DM. Consequently the two tracer species do not see exactly the same scalar
potential when epsilon is nonzero. To match those force laws, the generator uses

```text
Psi_star = -Phi_star,Newton - Phi_dm,epsilon
Psi_dm   = -Phi_star,epsilon - Phi_dm,epsilon
Phi(infinity) = 0
```

The spherical Plummer-kernel angular average is
2/[sqrt((r+s)^2+epsilon^2)+sqrt((r-s)^2+epsilon^2)].
Integrating this over shells includes the softened stellar contribution to the
DM potential; replacing it by the isolated NFW potential would be inconsistent.
Use PeTar's default --soft-eps 0 for the stellar component.

For each component, with q = d rho/d Psi, the inversion is

```text
f(E) = 1/(sqrt(8) pi^2) integral_0^E q'(Psi)/sqrt(E-Psi) dPsi
E = Psi - v^2/2
```

The code integrates piecewise-linear q segments analytically, including the
outer boundary segment to Psi=0. A materially negative DF aborts generation;
only roundoff at a relative 1e-8 cancellation threshold is clipped. In particular,
a cored isotropic stellar density is not compatible with every cusped potential.
Changing physical parameters (including the actual simulated softening) or a
different stellar model may be necessary. Increasing resolution only resolves
numerical error; it does not fix a physically negative DF. See
[Sanchez Almeida et al. (2023)](https://www.iac.es/en/science-and-technology/publications/can-cuspy-dark-matter-dominated-halos-hold-cored-stellar-mass-distributions).

The numerical radial interval is
[1e-3 min(a,rs,epsilon), 1e4 max(a,rt)]. Negligible inner/outer tails are omitted.
Potential and DF construction costs O(grid^2); CDF sampling is approximately
linear in particle count at fixed grid. Density reconstructed from the DF is
checked across the central 99.998% of each mass CDF, with a maximum allowed
relative error of 3%. Increase --dm-grid for a convergence study.
halo.dm.profile records r, both densities, both relative potentials, both DFs,
and both cumulative mass fractions. halo.dm.info records the complete halo
parameters, realized stellar mass, units, seed, output layout, errors and the
one common position/velocity offset subtracted from all particles.

This is an equilibrium of the smooth spherical model, sampled with finite-N
noise. Density/velocity checks and successful restart are not a substitute for
a long-term stability study at the desired particle mass and tree timestep.

## PeTar input

Use a PeTar binary configured with --enable-darkmatter and with external
potential mode off. For --petar-interrupt none use PeTar interrupt mode off.
For --petar-interrupt bse use PeTar BSE mode. The SSE McLuster compile option
does not select the PeTar row format; select it explicitly.

All output units are Msun, pc, Myr and **pc/Myr**, consistent with PeTar -u 1
(G = 0.00449830997959438 pc^3 Msun^-1 Myr^-2).

```sh
petar -u 1 -i 1 --dm-input halo.dm --dm-output-prefix dmdata halo.star
```

For a short input/integration check with the example above:

```sh
petar -u 1 -i 1 -s 0.0009765625 -o 0.0009765625 -t 0.0009765625 \
  --dm-input halo.dm halo.star
```

The stellar header is "0 Nstar 0"; the DM header is "0 Ndm 0 epsilon".
DM rows are exactly:

```text
mass x y z vx vy vz id ax ay az pot_dm pot_star
```

Initial accelerations/potentials and PeTar bookkeeping fields are zero, with
file ID zero requesting initialization. Both ID spaces start at one.
Subsequent paired data.K/dmdata.K snapshots are suitable for restart without
rerunning McLuster.

BSE output describes unevolved single stars (zero-age initialization).
--blackhole with --petar-interrupt bse writes kw=14 and core mass equal to the
current mass. Evolved-population, MOBSE/bseEmp-specific and external-field
layouts are not provided by this first version.

## Current supported combinations

NFW mode requires Plummer stars (-P 0), no segregation (-S 0), no fractal
substructure (-D 3), equilibrium (-Q 0.5), no primordial binaries (-B 0 -b 0),
no external tidal field (-t 0) or gas, zero stellar age (-e 0), astrophysical
units (-u 1), list output mode (-C 3), and positive Rh. Unsupported combinations
fail before model generation. These restrictions apply ONLY with --dm-nfw;
normal McLuster functionality remains available without it.

## Tests

```sh
make test-darkmatter
PETAR_DM=/absolute/path/to/petar make test-darkmatter
```

PETAR_DM must be a macro-on, interrupt-off, external-off executable. Tests
cover the softened shell kernel, the analytic Plummer DF limit, DF density
reconstruction, Jeans velocity moments, stellar contribution to the DM
potential/velocities, sampling CDFs, independent IDs, none/BSE column layouts,
invalid/negative-DF rejection, deterministic generation, and ordinary
Plummer/King/binary output equality between macro-on/off builds. The optional
PeTar test performs actual input, integration and paired restart.
MCLUSTER_BASELINE can point to a pre-change executable for before/after
comparison of the legacy modes.
